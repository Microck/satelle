---
title: Diagnose a Host
description: Run focused probes, refresh readiness evidence, and gather logs safely.
---

Start with local configuration because it does not contact a Host:

```sh
satelle config check --all --json
satelle config explain --host <alias> --json
```

Then run diagnostics:

```sh
satelle doctor --host <alias> --scope all --json
```

Use `--serial-probes` when deterministic one-at-a-time probing is useful. Use
`--events` for an NDJSON event stream; validation and transport errors remain
on stderr.

## Refresh live readiness evidence

`--refresh` is the explicit cache-mutation boundary. It reruns eligible live
probes instead of reading the current cached verdict.

```sh
satelle doctor --host <alias> --scope computer-use --refresh --timeout 120s --json
```

The timeout requires an explicit unit such as `30s` or `2m`. Refresh does not
perform setup, repair, service installation, or configuration changes.

## Read normalized logs

```sh
satelle logs --host <alias> --level warn --tail 200 --json
satelle logs --host <alias> --source codex_adapter --since 10m --json
```

Normal logs are designed for operational diagnosis and exclude raw provider
secrets. Export a redacted diagnostic bundle with `satelle support bundle` when
normal logs are insufficient. Do not archive the whole state directory as a
substitute.

Before sharing logs, redact Host aliases, usernames, addresses, tailnet names,
Session identifiers, local paths, prompts, transcripts, and desktop content.
Never share bearer tokens, provider secrets, private keys, or authorization
headers. Follow the repository security policy for suspected vulnerabilities.

## Reset an offline Host store

After stopping the Host, an explicitly approved `satelle host store reset`
can discard metadata even when an abandoned operation still holds a database
lease. Reset takes the exclusive filesystem ownership lock before deleting
anything, so a running Host still blocks it. Recordings remain unless
`--delete-recordings` is also approved.

Reset records its start in a durable file outside SQLite. On success it imports
the completed operation into the replacement database. If reset fails before
that database exists, the durable failure record remains available for retry.
Reset does not report the abandoned operation as completed or stop its external
processes. Stop those processes before resetting the store. When their state
cannot be established, reboot the machine before reset. Normal restart and
timeout recovery still retain uncertain leases; reset is an explicit deletion
of the stored history.
