Satelle sends durable Computer Use work to an operator-controlled Host. Start
with the [first session tutorial](/docs/tutorial/first-session), then use the
how-to guides for day-to-day operation.

Satelle 0.1.10 is available from npm, verified GitHub release artifacts, or
from source. Review the [installation methods](/docs/how-to/install-satelle)
before choosing an owner for upgrades and uninstall.

Every page in this version describes Satelle 0.1.10. The
[generated CLI and schema reference](/docs/reference/generated-cli) is checked
against the matching executable and public domain types in CI.

## Get to a result

The shortest supported path uses a local Host on macOS or Windows:

```sh
cargo build --release --locked -p satelle-cli
./target/release/satelle setup --host local-demo --dry-run
./target/release/satelle doctor --host local-demo --scope computer-use --refresh
./target/release/satelle run --host local-demo "Open the browser"
```

Save the returned `session_id`. It remains the public handle for status, logs,
steering, and stop requests after the original Controller exits.

## Current boundaries

- Controller commands run on Linux, macOS, and Windows.
- Native Computer Use Hosts run on macOS and Windows and must pass the live
  readiness probe.
- Controllers reach Hosts over local, direct HTTPS/WSS, and SSH-tunneled
  transports.
- Redacted support bundle export runs through `satelle support bundle`.
- The release-matched Agent Skill Bundle is embedded in the CLI and
  discoverable through `satelle skills`.

The documentation is organized as tutorials, how-to guides, workflows, reference,
and explanation. The repository `.facts` sheet is the specification source; these
pages describe only behavior verified in source and current CLI help.
