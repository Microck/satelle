`setup` application is transport-specific. Local setup is dry-run planning
only. SSH setup can apply the on-demand transport token handoff only. Direct
setup, persistent Host service installation, and SSH setup for broader
components are unavailable.

Direct and SSH-tunneled transports support ordinary Session operations. Live
`doctor` probes are currently local-only; unsupported transport/scope
combinations fail with a typed error.

Use `satelle <command> --help` as the exact option reference for the binary you
are running. Pre-release commands may change before the first stable release.
The [generated CLI and schema reference](/docs/reference/generated-cli) records
the complete help tree and public schema identifiers for Satelle 0.1.10.

## Output formats

Commands with a final result accept `--format human|json|compact-json|toon|markdown`.
`--json` is an exact alias for `--format json`. Each command's help lists its
supported formats.

| Format | Result |
| --- | --- |
| `human` | Command-specific text |
| `json` | The complete versioned JSON report, pretty-printed |
| `compact-json` | The same report as one minified JSON value followed by LF |
| `toon` | The complete JSON data model encoded as TOON 4.1 with two-space indentation and comma delimiters |
| `markdown` | The complete pretty JSON report inside one `json` fenced code block |
| `csv` | Available only for `skills list`, using the fixed columns below |

Structured formats retain schema identifiers, data values, array order, consent
requirements, and exit codes. JSON remains the canonical machine contract. TOON
preserves signed and unsigned 64-bit integers, escapes C0 control characters,
and writes finite numbers as decimals; negative zero becomes zero. Decode a
Markdown result by reading the JSON inside its fenced block.

`satelle skills list --format csv` emits the RFC 4180 header
`schema_version,bundle_version,name,description`, followed by one record per
bundled skill in bundle order. Each row repeats the schema and bundle versions.
All data fields are quoted, embedded quotes are doubled, and records end in CRLF.
No nested fields are discarded to produce a table.

Structured final results suppress interactive prompts and implicit human events
under the same rules as JSON. Errors use the typed JSON contract on stderr unless
`--error-format` explicitly selects another error format. Unsupported formats fail
before configuration loading or Host access.

`logs` supports only human output and its existing JSON records. `--events json`
continues to select an NDJSON event stream. It cannot combine with `--json` or
any explicit `--format`; `doctor --events` has the same restriction.

## Session commands

`run` and `steer` accept `--host`, `--detach`, `--quiet`, `--verbose`,
`--events auto|human|json|none`, `--prompt-file`, `--yolo`, and `--no-yolo`.
The prompt can be an argument or `-` for stdin. `steer`, `status`, and `stop`
take a public `session_id` positional argument.

When experimental provider Computer Use is enabled, attached `run` and `steer`
JSON results include `provider_smoke` with `status`, `source`, `observed_at`,
`expires_at`, and `age_ms`. The source is `live`, `cache`, or `refresh`.
`--refresh-provider-smoke-test` forces `refresh` before prompt execution.
Provider fingerprints, prompts, transcripts, and desktop content are excluded.

## Raw protocol exports

Use `satelle run --raw-protocol --output <path>` or
`satelle steer <session_id> --raw-protocol --output <path>` to capture the
selected Turn's Codex app-server JSON messages. Satelle shows the full
sensitivity warning before capture starts. Interactive use requires
confirmation. Noninteractive use requires both `--no-input` and `--yes`.
Raw capture cannot run with `--detach`.

The invoking CLI writes one private `satelle.raw-diagnostics.v1` JSON file,
then acknowledges that write to the Host. Satelle does not upload or cache the
file. The Host redacts known credentials before transfer, caps one capture at
8 MiB, keeps at most eight pending exports, and discards unacknowledged data
ten minutes after the Turn finishes or when the Host restarts. Inspect the
artifact before sharing it because unknown secrets and visible session content
can remain after redaction.

## Desktop snapshots

Use `satelle desktop snapshot --host <alias> --output <path>` to capture the
current visible desktop from one trusted Host and Desktop Binding. The command
shows the exact local output path, PNG format, redaction policy, storage effect,
and visual risks before asking for confirmation. It requires an interactive
terminal and one confirmation for that invocation. `--no-input`, redirected
stdin, or declined consent fails before capture.

The Host checks native capture permission, holds the Desktop Binding's Control
Lease during capture, removes PNG metadata, and transfers the artifact only to
the invoking Controller. The Controller writes a new owner-only file without
replacing an existing path, then acknowledges publication. The Host stores only
bounded audit metadata. It does not store pixels, thumbnails, OCR text, prompts,
transcripts, or output artifact contents. The PNG can still contain visible app
content, notifications, credentials, and personal data, so inspect it before
sharing it.

## Telemetry

Use `satelle telemetry status` for the local Controller. Add `--host <alias>`
to read an authenticated Host status. The result reports enabled state,
endpoint origin, buffered count and bytes, oldest record age, last delivery
outcome, and the excluded data categories. It never resolves or prints the
authorization Secret Source.

Opt-in telemetry contains bounded operation duration, outcome class, typed
error code, retry count, queue depth, and optional CPU and peak-memory values.
Resource attributes are limited to Satelle version, component kind, platform
class, and the configured deployment label. It excludes Host and Principal
identities, Session and Turn identifiers, arguments, prompts, transcripts,
desktop content, paths, addresses, secrets, artifacts, and provider payloads.

Failed delivery uses an owner-private local queue capped at 10 MiB and 24
hours. The oldest records are removed first. Collection and delivery do not
hold command or Host request completion open. Setting `enabled = false` stops
new capture, deletes that component's unsent queue, and makes no collector
request.

## Doctor options

`doctor` accepts `--host`, `--scope`, `--refresh`, `--timeout`,
`--serial-probes`, `--events`, and `--no-input`. `--timeout` is valid for an
eligible refresh scope and requires explicit units.

`doctor --scope provider --refresh` runs the provider smoke probe as a
diagnostic, updates the normal Host readiness cache, and reports whether the
result was refreshed. It does not create a Session or admit a prompt Turn.

## Support bundles

`satelle support bundle --host <alias> --output <path>` writes a private local
archive. It includes configuration shape, versions, readiness, normalized
logs, transport diagnostics, and setup-ledger summaries. It does not upload
the archive.

`setup_ledger.json` contains the 200 most recent Host maintenance operations,
ordered by start time. Each entry reports operation kind, status, timestamps,
and counts of planned, started, completed, failed, skipped, and uncertain
actions. `truncated` reports omitted older operations. Private references,
action labels, recovery text, and raw subprocess streams are excluded.

If a category cannot be read, the manifest lists it under `not_collected` with
the failure reason. An available empty history is reported as collected.

## Raw setup and repair subprocess output

Use `--raw-subprocess-output --output <path>` with `satelle setup` or
`satelle repair` to export selected redacted subprocess stdout from that one
invocation. Noninteractive use requires `--no-input --yes` as explicit raw
diagnostic consent. The command refuses an existing output path and does not
support this export in dry-run mode.

The artifact includes stable command identifiers, timestamps, exit status,
and redaction metadata. Satelle excludes token-bearing subprocesses, provider
traffic, prompts, transcripts, screenshots, and recordings. It does not add
this output to logs, setup history, status, Doctor, Operator Log Files, caches,
support bundles, or automatic uploads.

## Host version compatibility

Use `satelle host update --host <alias> --component host --version <version>`
to select a compatible stable release. Add `--dry-run --json` to inspect its
plan. Without `--version`, the target is the invoking CLI's exact release.
Explicit selection requires a remote Host and cannot include Codex components.
The following compatibility checks apply to explicit selection.

| Decision | Policy |
| --- | --- |
| Version skew | Stable patch releases within the same major/minor series |
| Protocol | One exact supported protocol; no fallback negotiation |
| Storage | Current and selected releases must use the CLI's storage schema |
| Features | Use the selected Host's advertised capabilities and normal readiness checks |
| Upgrade order | Upgrade the CLI first when the selected release requires a newer minimum CLI |
| Downgrade | Requires an explicit lower version and the same compatibility checks |
| Integrity | Verify `satelle-compatibility.json` against checksums and signed release attestations before planning; verify the platform archive before upload |
| Recovery | Resume the recorded update operation with its pinned version and artifact digest using the reported `satelle repair --run` command |

Missing or invalid compatibility metadata blocks explicit selection. The
metadata declares `schema_version`, `version`, `protocol_version`,
`storage_schema_version`, and `minimum_cli_version`. There are no update
channels or implicit latest-release selections.

The version option selects this update's target. It does not create a permanent
version pin for future setup, repair, or missing-daemon bootstrap operations.

## Host update plain records

`satelle host update --plain` writes UTF-8, LF-terminated records to stdout.
Fields are separated by TAB, with no header row:

| Position | Field | Values |
| --- | --- | --- |
| 1 | `schema` | `satelle.host.update.plain.v1` |
| 2 | `host` | Selected Host alias |
| 3 | `component` | `host_daemon`, `host_daemon_service`, `codex_runtime`, `codex_native_computer_use`, or `unknown` when planning fails before targets are known |
| 4 | `phase` | `plan`, `apply`, or `postcheck` |
| 5 | `status` | `planned`, `unchanged`, `skipped`, `succeeded`, `failed`, `postcheck_failed`, or `cancelled` |
| 6 | `current_version` | Observed version, or `-` |
| 7 | `target_version` | Selected version, or `-` |
| 8 | `changed` | `true` when this target has a confirmed applied action, otherwise `false` |
| 9 | `restart_required` | `true` or `false` from this target's plan |
| 10 | `error_code` | Typed error token with hyphens replaced by underscores, or `-` |
| 11 | `recovery_command` | Shell-safe command, or `-` |

Inside fields, backslash, TAB, LF, and CR become `\\`, `\t`, `\n`, and `\r`.
The v1 field order, escaping, and token meanings are fixed. A command emits one
plan record per target and, when it reaches application, one terminal record
per target. Completed targets retain their outcomes when another target fails.
Dry-runs and already-current targets do not require confirmation.

`--plain` conflicts with `--json` and every explicit `--format` value. It keeps
diagnostics and prompts on stderr, suppresses colors and human summaries, and
uses the same consent rules and exit codes as the equivalent update command.
`--quiet` does not suppress plain records. JSON remains the complete report.

## Unavailable command families

Commands can appear in `--help` before their implementation is complete.
Host stop/restart currently return typed not-implemented errors. See
[Move Host storage](/docs/how-to/move-host-storage) for migration, cleanup,
and interruption recovery. The embedded Agent Skill Bundle is
version-matched to this source tree and available through `satelle skills`.
