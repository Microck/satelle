Global options include `--no-color`, `--profile <name>`, and
`--error-format human|json`. Most state-reading commands also accept `--json`.

| Command | Purpose |
| --- | --- |
| `satelle setup` | Plan Host onboarding and apply the SSH token handoff |
| `satelle repair` | Repair a Host from live readiness evidence and retained action-ledger state |
| `satelle doctor` | Run diagnostic probes |
| `satelle config check` | Validate one or all local contexts |
| `satelle config explain` | Explain effective values and sources |
| `satelle paths` | Print resolved config, state, cache, and log paths |
| `satelle host start` | Run Host Daemon mode |
| `satelle host trust --host <alias>` | Authenticate a direct Host and pin its stable identity |
| `satelle host status` | Read Host status |
| `satelle host sessions` | List eligible native desktop sessions |
| `satelle host update` | Update the current Host or one selected remote Host |
| `satelle run` | Create a Session and first Turn |
| `satelle steer` | Add a follow-up Turn to a Session |
| `satelle status` | Read authoritative Session state |
| `satelle stop` | Stop the active Turn |
| `satelle logs` | Read normalized retained Host logs |
| `satelle mcp serve` | Serve the MCP interface over stdio |
| `satelle mcp install` | Configure a supported AI client to call Satelle MCP |
| `satelle skills list` / `get` / `path` | Discover and materialize the release-matched Agent Skill Bundle |
| `satelle support bundle` | Export a redacted support bundle |
| `satelle self update` | Update the local executable with an optional single-Host handoff |
| `satelle completions` | Generate shell completions |

`setup` application is transport-specific. Local setup is dry-run planning.
SSH setup applies the on-demand transport token handoff.

Direct and SSH-tunneled transports support ordinary Session operations. Live
`doctor` probes run locally; unsupported transport/scope combinations fail
with a typed error.

Use `satelle <command> --help` as the exact option reference for the binary you
are running.
The [generated CLI and schema reference](/docs/reference/generated-cli) records
the complete help tree and public schema identifiers for Satelle 0.1.11.

## Session commands

`run` and `steer` accept `--host`, `--detach`, `--quiet`, `--verbose`,
`--events auto|human|json|none`, `--prompt-file`, `--yolo`, and `--no-yolo`.
The prompt can be an argument or `-` for stdin. `steer`, `status`, and `stop`
take a public `session_id` positional argument.

When experimental provider Computer Use is enabled, attached `run` and `steer`
JSON results include `provider_smoke` with `status`, `source`, `observed_at`,
`expires_at`, and `age_ms`. The source is `live`, `cache`, or `refresh`.
`--refresh-provider-smoke-test` forces `refresh` before prompt execution.
Provider fingerprints, prompts, transcripts, and desktop content are excluded.

## Doctor options

`doctor` accepts `--host`, `--scope`, `--refresh`, `--timeout`,
`--serial-probes`, `--events`, and `--no-input`. `--timeout` is valid for an
eligible refresh scope and requires explicit units.

`doctor --scope provider --refresh` runs the provider smoke probe as a
diagnostic, updates the normal Host readiness cache, and reports whether the
result was refreshed. It does not create a Session or admit a prompt Turn.
