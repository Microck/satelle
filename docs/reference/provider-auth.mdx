---
title: Provider authentication
description: Configure Host-resolved Secret Sources without exposing provider secrets.
---

Provider authentication belongs to the Host. User configuration stores only a
descriptor that tells the Host where to resolve secret material.

## Environment

```toml
[hosts.local-demo.provider_auth.openai]
kind = "environment"
variable = "OPENAI_API_KEY"
```

## Owner-only file

```toml
[hosts.local-demo.provider_auth.openai]
kind = "file"
path = "/absolute/path/to/openai-token"
```

A File descriptor can also use `path = "~/.config/provider/token"`. Satelle
expands it on the Host using the daemon process account's OS home. Linux and
macOS accept `~` and `~/`; Windows also accepts `~\`. Named-user forms such as
`~alice`, other relative paths, environment substitutions, and command
substitutions are invalid. The same owner-only file checks apply after expansion.

Config inspection does not open the file. `config explain
--show-secret-references` expands paths only for a known local on-demand account;
remote references report `remote_home_not_checked`.

## Operating-system credential store

```toml
[hosts.local-demo.provider_auth.openai]
kind = "credential-store"
service = "satelle"
account = "openai"
```

## Host-managed store

```toml
[hosts.local-demo.provider_auth.openai]
kind = "host-store"
name = "openai-production"
```

## Executable helper

```toml
[hosts.local-demo.provider_auth.work]
kind = "executable-helper"
argv = ["/opt/credentials/provider-helper", "--account", "work"]
timeout = "10s"
environment = { HELPER_PROFILE = "work" }
```

The Host runs the helper only when a provider smoke test or execution needs
authentication. The helper exchanges one JSON request and response over pipes
and receives a restricted environment. See the
[helper protocol and limits](/docs/reference/configuration#credential-helpers).
Config inspection never runs helpers and always redacts their arguments and
environment references, including with `--show-secret-references`.

## Interactive File provisioning

Host-resolved Secret Sources are the normal path. The only raw-secret exception
is interactive setup for a File descriptor. In a human terminal, setup shows
the exact Host alias and destination path, disables terminal echo while reading
the value, and asks for confirmation immediately before authenticated
transmission to that Host.

`--yes`, Trusted Profiles, JSON output, and `--no-input` cannot authorize this
flow. The secret value is not accepted through command arguments or
configuration and must not appear in logs, support artifacts, or agent
conversation. A declined or failed replacement preserves the prior authorized
Host value.

Run a noninteractive setup plan to discover missing input without exposing a
secret:

```sh
satelle setup --host local-demo --component provider-auth --dry-run --no-input --json
```

Raw secret values must not appear in command arguments, project configuration,
logs, support artifacts, or agent conversation. `config explain` returns
redacted descriptors by default. The explicit `--show-secret-references` flag
shows descriptor locations and names, not the secret values they resolve.
