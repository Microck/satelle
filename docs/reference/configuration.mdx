title: Configuration reference
description: User and project configuration, precedence, profiles, paths, and Host bindings.
---

Run `satelle paths --json` for the effective paths on the current operating
system. `SATELLE_HOME` relocates the config, state, cache, and log roots.
`SATELLE_CONFIG_FILE`, `SATELLE_STATE_DIR`, `SATELLE_CACHE_DIR`, and
`SATELLE_LOG_DIR` override individual absolute paths.

Configuration selects behavior; it does not make an unimplemented transport
operation available. Local setup is planning-only, SSH setup is limited to the
on-demand transport token handoff, and direct setup is unavailable.

## User configuration

User configuration owns concrete Host bindings and sensitive descriptors:

```toml
default_host = "local-demo"
model_alias = "default-model"
provider_alias = "openai"

[telemetry]
enabled = true
otlp_endpoint = "https://collector.example"
deployment_label = "controller-production"

[telemetry.authorization]
kind = "environment"
variable = "SATELLE_OTLP_TOKEN"

[hosts.local-demo]
transport = "local"
adapter = "codex"
setup_mode = "on-demand"
daemon_idle_timeout = "10m"
native_readiness_cache_ttl = "5m"
provider_smoke_success_cache_ttl = "1440m"
provider_smoke_failure_cache_ttl = "10m"
session_metadata_retention = "30d"
sqlite_log_retention = "45d"
operator_log_retained_files = 12
platform_log_sink = false
yolo = false

[hosts.local-demo.timeouts]
native_readiness = "120s"
provider_smoke_test = "2m"

[hosts.local-demo.telemetry]
enabled = true
otlp_endpoint = "https://host-collector.example"
deployment_label = "desktop-production"
```

Host fields include `transport`, `adapter`, `address`, `network`, `timeouts`,
desktop selection, daemon path overrides, `setup_mode`, experimental-provider
opt-in, daemon and readiness cache TTLs, Host-scoped `yolo`, project-selection
permission, direct-transport identity and trust fields, and provider Secret
Source descriptors. `session_metadata_retention` and `sqlite_log_retention`
accept `h` or `d` values from 7 days through 365 days. They are independent.
`operator_log_retained_files` keeps 1 through 100 rotated 10 MiB files and does
not change SQLite log retention.

Set `platform_log_sink = true` on a user-owned Host Binding to mirror the same
redacted summaries to journald on Linux, Windows Event Log, or macOS unified
logging. The setting is off by default. The operating system owns retention and
queries for this mirror. A sink failure appears as an informational `config`
Doctor finding and never changes SQLite logs, operator log files, or daemon
availability. Project configuration cannot enable the sink.

The top-level `telemetry` table controls Controller telemetry. A
`hosts.<alias>.telemetry` table controls telemetry emitted by that Host. Each
policy is off by default and must set both `enabled = true` and an
`otlp_endpoint`. The endpoint must be an HTTPS origin with no credentials,
query, fragment, or path. Loopback HTTP is allowed for a local collector.

Telemetry sends OTLP/HTTP traces and metrics to `/v1/traces` and `/v1/metrics`
on that origin. Optional bearer authorization comes from an `environment` or
absolute owner-only `file` Secret Source on the emitting machine. Satelle does
not accept an inline authorization value. Project configuration, profiles,
setup, bootstrap, package installation, `--yes`, and Trusted Profile consent
cannot enable telemetry.

The duration parser requires explicit units such as `500ms`, `30s`, or `2m`.
Configuration does not perform environment-variable interpolation.

## Explicit includes

Declare `include = ["hosts.toml", "profiles.toml"]` at the top of a config file.
Paths resolve relative to that file. Included files must be regular `.toml`
files inside the top-level config directory, or inside `.satelle` for project
configuration. Symlinks, globs, URLs, shell syntax, cycles, more than 64 levels,
and more than 256 loaded files are rejected.

Files apply in list order, then the including file applies last. User Host
Bindings, named profiles, and Trusted Profiles replace complete definitions;
included Host Bindings must supply their required fields. Project includes
keep the project schema and cannot define credentials, trusted consent, or
desktop authority. Every file is validated, including overridden definitions.

`config check` lists all checked files. `config explain --json` also reports
each file's parent and the exact file and TOML path behind each configured
value in `sources.files` and `sources.values`. These commands do not resolve
secret material.

## Named profiles

Profiles can select a Host and overlay model, provider, timeouts, daemon idle
timeout, native and provider readiness cache TTLs, experimental-provider opt-in,
output format, diagnostic log verbosity, Host-bound YOLO policy, and an explicit
user-owned Trusted Profile reference.

```toml
[profiles.work]
host = "local-demo"
provider_alias = "openai"
provider_smoke_success_cache_ttl = "720m"
provider_smoke_failure_cache_ttl = "5m"
log_verbosity = "debug"
trusted_profile = "maintenance"
session_metadata_retention = "30d"
sqlite_log_retention = "45d"
operator_log_retained_files = 12
yolo = false

[profiles.work.timeouts]
native_readiness = "90s"

[trusted_profiles.maintenance]
hosts = ["local-demo"]
command_families = ["setup", "repair"]
```

Select a profile with `--profile work`, `SATELLE_PROFILE=work`, or a config
default. Source matters: environment or project selection cannot activate
`yolo = true` or Trusted Profile consent. A Trusted Profile is never selected
implicitly by a same-name profile.

A Trusted Profile may set `expires_at = "2027-01-01T00:00:00Z"`. Use a quoted
RFC 3339 UTC timestamp. At that instant the grant expires. Omit `expires_at`
for a grant that lasts until you edit or remove it; Satelle never invents an
expiry. `config check --all` checks every Trusted Profile, and `config explain`
reports `absent`, `active`, or `expired`. An expired grant cannot authorize a
mutation. Use explicit command consent or interactive confirmation, or review
the expiry in the user file that defines it.

Diagnostic verbosity accepts `off`, `info`, `debug`, or `trace`. Precedence is
`--log-verbosity`, then `SATELLE_LOG`, then profile and user configuration.
JSON command output never includes diagnostic logs.

For Phase 0 discovery, debug logs report stage budgets, request writes and
flushes, response line sizes, app-policy attempts, and child process outcomes.
They exclude raw arguments, configuration values, protocol bodies, and paths.
Enable debug logging on the process performing discovery; a Controller flag
does not change the verbosity of an already running Host Daemon. `RUST_LOG`
does not configure Satelle diagnostics.

Phase 0 rows in doctor JSON and event output include `phase0_budget_ms` when
the current refresh starts discovery. This is the useful-work budget after
the scheduler reserves cleanup time; zero means none remained when the worker
started. The budget survives a timeout even if
the worker's snapshot is discarded. Cached reads and unrelated probes omit
the field. Timeout timestamps and durations describe the current probe's
execution, not the collection time of older cached evidence. A native refresh
timeout uses the `computer-use.native.refresh` row.

User Host configuration sets the retention baseline. A selected user-owned
profile can override it. Project configuration cannot set destructive
retention.

## Project configuration

Satelle discovers `.satelle/config.toml` from the current directory upward.
Project configuration is shared intent, not authority:

```toml
default_host = "studio-mac"
provider_alias = "openai"

[hosts.studio-mac]
transport = "direct"

[hosts.studio-mac.timeouts]
native_readiness = "90s"
```

The matching Host alias must already exist in user configuration and permit
project selection. Project configuration cannot define addresses, TLS trust,
tokens, desktop identity, daemon paths, Secret Sources, telemetry, mutation
consent, Trusted Profiles, destructive retention, or YOLO enablement.

## Inspect the result

```sh
satelle config check --all --json
satelle config explain --host local-demo --json
```

`config explain` redacts Secret Source references unless
`--show-secret-references` is explicit. It never reads or prints secret
material.

Direct Host Bindings can set `client_certificate.certificate_file` and
`client_certificate.private_key_file` to absolute PEM paths for mutual TLS.
These user-level references follow the same explicit disclosure rule. The
existing `ca_bundle` controls trust in the Host server, while the client
certificate authenticates the Controller connection. See
[client certificate setup](/docs/how-to/connect-remote#require-client-certificates).

## Repair local configuration

```sh
satelle config repair --dry-run --json
satelle config repair --yes
satelle config repair --file .satelle/config.toml --dry-run
```

Repair fixes unambiguous key spelling such as `default-host` to `default_host`.
It preserves values and comments. Colliding keys, other misspellings, invalid
values, and diagnostics that require a choice need manual correction.

The default target is the local user config file. Use `--file` to select a
loaded include or a project config file. The command validates the resulting
configuration through the normal loader before offering any write.

A dry-run shows a unified diff of redacted JSON, backup paths, digests, and a
restore command. It writes nothing. An apply invocation builds a fresh plan,
checks the input files again, and verifies a private byte-for-byte backup under
the local state directory before replacing the selected config file. Keep the
reported backup until the configuration is verified.

Use `--yes` to accept the planned changes. Otherwise an interactive invocation
shows the preview and asks once; choosing No leaves the file unchanged.
`--no-input` needs `--yes` or a user-owned Trusted Profile with `config_repair`
consent. Trusted Profile consent also requires an explicit `--host` and edits
confined to that Host Binding. It cannot authorize project, root, profile, or
trust-policy edits.

Config repair never contacts a Host, resolves a Secret Source, changes a
service, or writes a setup ledger.

## Credential helpers

A user-owned provider binding can resolve credentials with an executable on
the target Host. The executable and its settings must exist on that Host.
Project configuration cannot define a helper.

```toml
[hosts.local-demo.provider_auth.work]
kind = "executable-helper"
argv = ["/opt/credentials/provider-helper", "--account", "work"]
timeout = "10s"
environment = { HELPER_PROFILE = "work" }
```

Reference `work` from a provider binding's `auth_source`. `argv[0]` must be an
absolute executable path for the Host's operating system. Satelle passes the
remaining arguments literally. Shell launchers, inline interpreter commands,
and standalone shell operators are rejected. Satelle does not expand shell
syntax or search `PATH`. `timeout` defaults to `10s` and requires explicit
units when set.

The Host sends one UTF-8 JSON object, then closes stdin:

```json
{"schema_version":1,"operation":"resolve","provider_alias":"work","resolved_provider":"openai","host_alias":"local-demo"}
```

Requests contain no existing credentials or prompt text and are limited to
2 KiB. The helper returns exactly one UTF-8 JSON object on stdout:

```json
{"schema_version":1,"status":"success","secret":"example-provider-credential"}
```

Failure responses use `status = "error"` or `"interaction_required"` and a
nonempty `code` instead of `secret`. Unknown fields, nonzero exits, invalid or
multiple JSON values, NULs, empty secrets, and output over 64 KiB fail before
prompt execution. A timeout reports `credential-helper-timeout`. Helpers have
no terminal; Satelle discards stderr and does not answer interactive prompts.
The Host terminates the helper process group when the operation ends.

The inherited environment contains only `HOME`, `USERPROFILE`, `SystemRoot`,
`WINDIR`, `TMPDIR`, `TMP`, `TEMP`, `LANG`, and `LC_ALL` when present. Explicit
`environment` entries add literal, non-secret helper settings. Keys use ASCII
letters, digits, and underscores, cannot start with a digit, and cannot use
the reserved `SATELLE_` prefix. Existing provider or transport credentials are
never inherited.

`config check` and `config explain` never execute a helper. Explain reports
the kind, source, and effective timeout. It always redacts executable paths,
arguments, environment key names, and values, even with
`--show-secret-references`. Satelle never includes helper stdout, stderr,
response error codes, or resolved secrets in diagnostics or stored state.
